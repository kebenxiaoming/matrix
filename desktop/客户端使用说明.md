# 视频矩阵分发客户端

把原 `matrix` 命令行脚本封装成的 Windows 桌面客户端。双击即可运行，无需安装 Python、MySQL、Redis。

> 手上没有 exe、想直接从源码跑？看 [从源码运行.md](从源码运行.md)。

## 一、启动

双击目录里的 **`视频矩阵分发.exe`**。

- 首次启动会在 exe 同级生成 `data` 目录，存放数据库、账号 cookie、配置和日志
- 整个文件夹可以直接拷贝到别的电脑继续用（账号登录状态会一起带走）
- 想换位置就移动整个文件夹，不要只移动 exe

## 二、第一次使用：登录账号

1. 左侧点 **账号管理**
2. 右上角 **＋ 添加账号**，选择平台（抖音 / 视频号 / 小红书 / 快手）
3. 程序会自动弹出一个浏览器窗口，用手机上的对应 App 扫码
4. 扫码成功后浏览器自动关闭，账号出现在列表里，状态显示 **正常**

注意事项：

- **抖音**：扫码后有时会要求身份验证，按浏览器里的提示完成短信验证即可
- **视频号**：登录后需要等几秒，程序还要读取昵称和头像
- **小红书**：签名走本机浏览器计算，登录时会比其它平台慢 10 秒左右，属于正常现象
- 一个平台可以登录多个账号，互不影响

## 三、发布视频

1. 左侧点 **新建发布**
2. 点虚线上方区域选择视频（也可以直接把视频文件拖进去）
3. 选择封面图 —— **视频号、快手、小红书必须提供封面**，抖音可以不填
4. 填写标题、话题标签（空格分隔）、定位
5. 右侧勾选要发布到的账号，可以跨平台多选
6. 需要定时发布就勾上「定时发布」并选时间
7. 点 **加入发布队列**

任务会出现在 **发布队列** 页。**队列默认不会自动运行**，需要在队列页点 **▶ 启动队列**。

队列是串行执行的：一个任务完成后再做下一个，中间会按「任务间隔」等待，避免动作过快被平台风控。

## 四、界面说明

| 页面 | 作用 |
| --- | --- |
| 概览 | 账号与任务总量、最近任务 |
| 账号管理 | 添加/重新登录/删除账号 |
| 新建发布 | 一次性把同一个视频分发到多个账号 |
| 发布队列 | 启停队列、查看进度、重试失败任务 |
| 运行日志 | 实时日志，可导出 |
| 设置 | 任务间隔、重试次数、浏览器通道、签名方式 |

## 五、常见问题

**Q：扫码登录成功了，客户端却还显示「未登录」？**

先看弹窗提示的原因。程序判定登录成功的依据是**平台下发了登录 cookie**，不是页面上显示什么：

- 等待上限 **5 分钟**，超时会弹出「登录未完成」并说明原因，重新点一次「去登录」即可
- 扫码后如果抖音要求**身份验证**，请在浏览器窗口里直接完成短信验证，验证完不要关窗口，程序会自动继续
- 如果提示「登录窗口被关闭」，说明浏览器被提前关掉了，重来一次
- 失败的完整过程在 **运行日志** 页，也可以查看 `data/logs/uploader.log`

**Q：视频号发布失败，提示转码或编码错误？**
视频号要求视频是 H.264 编码。程序会优先调用系统安装的 Google Chrome，没装则回退到内置 Chromium。建议安装 Chrome 以提高成功率。也可以在「设置 → 视频号浏览器」里手动指定。

**Q：任务显示「登录失效」？**
平台会定期让 cookie 过期。到账号管理页点该账号的 **重新登录** 扫码即可，队列里的任务点「重试」会重新执行。

**Q：小红书登录没有弹出浏览器？**
小红书是接口扫码，二维码会以弹窗形式出现在客户端里，用小红书 App 扫那个二维码即可，有效约 2 分钟。

**Q：小红书发布卡在签名？**
签名需要在本机启动一个无头浏览器。第一次会比较慢（约 10 秒），后续复用同一个浏览器实例。如果持续失败，到「设置 → 小红书签名」确认选的是「内置签名」。

**Q：关掉窗口后任务还在跑吗？**
不会。「发布中」的任务会被中断，下次启动后需要在队列页点重试。

**Q：数据存在哪？**
默认在 exe 同级的 `data` 目录。设置页有「打开数据目录」按钮。里面的 `matrix.db` 是 SQLite 数据库，`accounts` 是各平台 cookie。

**Q：能同时跑多个任务吗？**
当前是单队列串行，避免同一浏览器实例冲突和平台风控。需要并发可以开多个客户端实例（不推荐同账号并发）。

## 六、合规提醒

本项目基于开源 matrix 脚本封装，仅供个人学习与自有账号的内容分发使用。请遵守各平台的用户协议与内容规范，不要用于批量养号、搬运侵权内容等违规用途。
